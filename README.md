# poisq (v0.0.1)

**poisq** — умный поиск и модуль текстов песен (Lyrics) для музыкального сервера [Navidrome](https://www.navidrome.org/).

Он объединяет две ключевые возможности:
1. **Интеллектуальный и быстрый поиск музыки:**
   - **Забыли переключить язык:** найдет *Nirvana* по запросу `Тшкмфтф` или *Кино* по запросу `rbyj`.
   - **Написали по-русски на слух:** поймет `офспринг` как *The Offspring*, а `металика` как *Metallica*.
   - **Опечатались:** исправит случайные ошибки вроде `щеаызкштп` или `splean` на лету.
   - **Ввели только первые буквы:** моментально подскажет исполнителя уже с 1–2 символов (например, `оф` -> *Offspring*).
2. **Синхронизированные тексты песен (Lyrics) с акцентом на русский язык:**
   - **Автоматический поиск слов:** мгновенно подтягивает синхронизированные построчные тексты (**LRC**) и plain-тексты прямо во время воспроизведения в **Feishin**, **Amperfy**, **Symfonium**, **Play:Sub**.
   - **Русскоязычные и глобальные источники:** поиск в крупнейших базах — **Яндекс Музыка**, **Genius (RU)**, **Musixmatch**, **LRCLIB**, **Text-pesni / Amalgama**.
   - **Подключение источников вручную:** поддержка любых внешних URL по протоколам LRCLIB / lrcmux.
   - **Безопасное кэширование:** тексты сохраняются в SQLite и оперативной памяти, не загрязняя файлы медиатеки на диске.

Сервис работает полностью прозрачно и незаметно: запросы обрабатываются быстрее чем за 0.5 мс и сразу отображаются во всех клиентских приложениях и веб-интерфейсе.

## 🚀 Быстрый старт (Docker Compose)

Запуск связки **Navidrome + poisq** занимает меньше минуты.

### 1. Создайте файл `docker-compose.yml`:

```yaml
services:
  # Официальный музыкальный сервер Navidrome
  navidrome:
    image: deluan/navidrome:latest
    container_name: navidrome
    # user: 1000:1000 # Опционально: укажите UID:GID владельца папки с музыкой при необходимости
    restart: unless-stopped
    environment:
      ND_SCANSCHEDULE: "1h"
      ND_LOGLEVEL: "info"
      ND_SESSIONTIMEOUT: "24h"
      ND_BASEURL: ""
    volumes:
      - /path/to/your/music:/music:ro # Укажите путь к вашей папке с музыкой на сервере
      - navidrome_data:/data
    # Порт 4533 можно оставить для прямого доступа к Navidrome или закрыть,
    # чтобы все клиентские приложения подключались через poisq (порт 4534)
    ports:
      - "4533:4533"

  # Умный реверс-прокси и обогатитель поиска для Navidrome
  poisq:
    image: ghcr.io/f5go/poisq:latest
    container_name: poisq
    restart: unless-stopped
    depends_on:
      - navidrome
    ports:
      - "4534:4534"
    environment:
      LISTEN_ADDR: ":4534"
      NAVIDROME_URL: "http://navidrome:4533"
      NAVIDROME_DB_PATH: "/data/navidrome.db"
      SYNC_INTERVAL: "2m"
      ENRICH_SQLITE_FULLTEXT: "true"
      LOG_LEVEL: "info"
      # Подсистема текстов песен (Lyrics)
      LYRICS_ENABLED: "true"
      LYRICS_CACHE_TTL: "720h" # 30 дней
      LYRICS_CACHE_MAX_ENTRIES: "5000" # Лимит записей в оперативной памяти
      LYRICS_PROVIDERS: "yandex,genius,musixmatch,lrclib,amalgama"
      # LYRICS_CUSTOM_SOURCES: "https://my-custom-lrclib.local"
    volumes:
      # Общий том данных с Navidrome для прямого безопасного доступа к navidrome.db в WAL-режиме
      - navidrome_data:/data

volumes:
  navidrome_data:
```

### 2. Запустите контейнеры:

```bash
docker compose up -d
```

### 3. Подключите плеер:

В вашем приложении (**Feishin**, **Amperfy**, **Play:Sub**, **Arpeggi**) или в браузере укажите адрес:
```
http://<IP_ВАШЕГО_СЕРВЕРА>:4534
```
Логин и пароль используются те же, что и в Navidrome.

## 1. Архитектурная концепция

Сервис использует гибридную двухслойную модель:

```
[ Клиент (Feishin, iOS, Web) ]
               │
               ▼
┌──────────────────────────────────────────────┐
│        poisq (:4534)                         │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 1. Transparent Reverse Proxy (< 0.5ms) │  │
│  │    - 99% трафика идет напрямую         │  │
│  │    - Перехват /rest/search3 и /api/*   │  │
│  │    - Умный рерайтинг / Fan-out         │  │
│  └───────────────────▲────────────────────┘  │
│                      │                       │
│  ┌───────────────────┴────────────────────┐  │
│  │ 2. In-Memory Vocabulary & Fuzzy Index  │  │
│  │    - Trie (префиксный автокомплит)     │  │
│  │    - Damerau-Levenshtein (опечатки)    │  │
│  │    - QWERTY <-> ЙЦУКЕН маппер          │  │
│  └───────────────────▲────────────────────┘  │
│                      │ чтение                │
│  ┌───────────────────┴────────────────────┐  │
│  │ 3. Background SQLite Index Enricher    │  │
│  │    - WAL-безопасные короткие транзакции│  │
│  │    - Обогащение full_text в SQLite     │  │
│  └───────────────────▲────────────────────┘  │
└──────────────────────┼───────────────────────┘
                       │ прямой доступ к WAL
                       ▼
┌──────────────────────────────────────────────┐
│        Navidrome (:4533) + navidrome.db      │
└──────────────────────────────────────────────┘
```

### In-Memory словарь и нечеткий индекс
- Считывает таблицы `artist`, `album` и `media_file` из базы `navidrome.db`.
- Формирует в памяти потокобезопасное префиксное дерево (Trie) и индекс слов с весами популярности (`play_count` + тип сущности).
- Автоматически обогащает колонку `full_text` записей фонетическими транслитерациями (`The Offspring` -> `[poisq: офспринг оффспринг]`, `Кино` -> `[poisq: kino]`) с отслеживанием контрольных сумм в таблице `_poisq_enrichment`, исключая повторные обновления.

### Real-Time перехват и умный рерайтинг (< 0.5 мс)
- **Короткие запросы (1–3 символа) — Режим автокомплита:**
  Без нечеткого поиска. Генерирует варианты раскладки и транслита, ищет по префиксному дереву Trie и возвращает лучший канонический префикс.
- **Длинные запросы (4+ символов) — Нечеткий поиск:**
  Генерирует варианты (исходный, смена раскладки, фонетический транслит) и рассчитывает расстояние Дамерау-Левенштейна (допустимо расстояние $\le 1$ для 4–5 символов, $\le 2$ для 6+ символов).
- **Параллельный Fan-out:**
  При неоднозначных коротких префиксах (например, запрос `"ja"` может относиться к `"Jane Air"` или быть раскладкой `"оф"` для `"Offspring"`) прокси параллельно отправляет 2 запроса в Navidrome, объединяет результаты с дедупликацией по ID (JSON и XML) и возвращает единый ответ клиенту.

### Поддержка Multi-Library (Navidrome v0.58+)
- Полная прозрачность и сохранение параметров `musicFolderId`, `u`, `t`, `s`, `p`, `v`, `c`, `f` для изолированных и комбинированных медиатек.

## 2. Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `LISTEN_ADDR` | `:4534` | Адрес и порт, на котором слушает `poisq` |
| `NAVIDROME_URL` | `http://navidrome:4533` | Внутренний URL сервера Navidrome |
| `NAVIDROME_DB_PATH`| `/data/navidrome.db` | Путь к файлу SQLite базы данных Navidrome |
| `SYNC_INTERVAL` | `2m` | Интервал фоновой синхронизации словаря и обогащения |
| `ENRICH_SQLITE_FULLTEXT` | `true` | Включение безопасного обогащения столбца `full_text` |
| `LOG_LEVEL` | `info` | Уровень логирования (`debug`, `info`, `warn`) |

### 3. Диагностика и безопасность

В целях безопасности и работы в открытых сетях, микросервис `poisq` спроектирован по принципу максимальной защиты:
- **Диагностические эндпоинты закрыты по умолчанию (`ENABLE_DEBUG_API=false`)**: любые обращения к `/_smart/*` возвращают `404 Not Found`, чтобы прокси не выдавал своего присутствия сторонним сканерам.
- **Полное отсутствие мутирующих HTTP-методов**: в API нет небезопасных эндпоинтов записи или выполнения команд. Контейнер может работать с полностью защищенной файловой системой `read_only: true`.
- **Защита от SQL-инъекций**: строгая валидация имен таблиц и столбцов по белому списку перед обращением к SQLite.
- **Защита от DoS и истощения памяти**: чтение ответов Navidrome и внешних синхронизаций ограничено потоковыми лимитами (`io.LimitReader`).
- **Защита от спуфинга заголовков**: извлечение и валидация реального IP-клиента через `net.SplitHostPort` перед проксированием.

Для локальной отладки включите переменную окружения `ENABLE_DEBUG_API=true`:

```bash
# Проверка работы поискового анализатора
curl "http://localhost:4534/_smart/test?q=щеаызкштп"

# Просмотр активного словаря музыкальных алиасов (только чтение)
curl "http://localhost:4534/_smart/aliases"
```

### 3.2. Настройка музыкальных алиасов (aliases.json)

Сервис поставляется с обширной встроенной базой музыкального сленга и транслитераций (250+ групп). Кроме того:
1. **Автоматическая синхронизация**: `poisq` ежедневно обновляет список алиасов из официального репозитория GitHub в фоне без перезапуска.
2. **Пользовательский файл**: вы можете подключить свой собственный `aliases.json` в режиме "только чтение" (`:ro`) через volume docker-compose:
   ```yaml
   volumes:
     - /path/to/my_aliases.json:/data/aliases.json:ro
   ```
   Формат файла:
   ```json
   {
     "гражданка": "Гражданская Оборона",
     "соад": "System of a Down",
     "бг": "Аквариум"
   }
   ```

### 3.3. Модуль текстов песен (Lyrics) с акцентом на русский язык

`poisq` перехватывает запросы текстов песен по протоколам Subsonic и OpenSubsonic (`/rest/getLyrics`, `/rest/getLyricsBySongId`), обеспечивая мгновенную отдачу из локального кэша и интеллектуальный поиск в русскоязычных базах.

#### Возможности модуля:
1. **Каскадный опрос с приоритетом синхронизированного LRC**:
   - `Яндекс Музыка` (наибольшая база синхронизированных LRC для русских треков).
   - `Genius (RU)` (тексты рэпа, рока, поп, инди и андеграунда).
   - `Musixmatch` (мировая база с точной синхронизацией).
   - `LRCLIB` (открытый глобальный источник без ограничений).
   - `Amalgama-lab / Text-pesni` (эстрада, шансон, барды, переводы).
2. **Добавление источников вручную (Custom Sources)**:
   - Поддерживает любые внешние URL по протоколу LRCLIB/lrcmux через переменную `LYRICS_CUSTOM_SOURCES="https://my-lyrics-api.local"`.
3. **Безопасное кэширование по умолчанию**:
   - Тексты сохраняются в постоянном кэше (In-Memory LRU + SQLite в `/data`).
   - Медиатека на диске по умолчанию **не изменяется** (`LYRICS_SAVE_TO_DISK=false`). Запись `.lrc` файлов в `/music` включается только по явному желанию.
4. **Совместимость с официальным `nd-lyrics`**:
   - `poisq` предоставляет LRCLIB-совместимый API: `/lyrics/api/get` и `/lyrics/api/search`. В плагине `nd-lyrics` Navidrome можно указать `http://poisq:4534/lyrics/api` в качестве источника с наивысшим приоритетом.
5. **Диагностика**:
   - `/_smart/lyrics/test?artist=Кино&title=Группа+крови` — замер скорости и проверка работы каждого источника.
   - `/_smart/lyrics/sources` — список активных провайдеров.

## 4. Структура проекта (Header First & Модульность)

Кодовая база разделена на независимые модули, каждый файл начинается с обязательной шапки с описанием назначения:

```
├── cmd/
│   └── proxy/
│       └── main.go                 # Точка входа, graceful shutdown, фоновый тикер
├── internal/
│   ├── config/
│   │   └── config.go               # Загрузка и валидация конфигурации из ENV
│   ├── lyrics/                     # Подсистема текстов песен (Lyrics)
│   │   ├── types.go                # Доменные структуры: Lyrics, Line, SearchQuery
│   │   ├── config.go               # Конфигурация подсистемы lyrics
│   │   ├── cache.go                # Двухуровневый кэш (In-Memory LRU + SQLite)
│   │   ├── lrc_parser.go           # Парсинг и генерация формата [mm:ss.xx]
│   │   ├── writer.go               # Опциональная безопасная запись .lrc на диск
│   │   ├── provider.go             # Интерфейс Provider
│   │   ├── provider_yandex.go      # Адаптер Яндекс Музыки (LRC)
│   │   ├── provider_genius.go      # Адаптер Genius RU (Plain)
│   │   ├── provider_musixmatch.go  # Адаптер Musixmatch (LRC)
│   │   ├── provider_lrclib.go      # Адаптер LRCLIB (LRC)
│   │   ├── provider_amalgama.go    # Адаптер Amalgama / Text-pesni (Plain)
│   │   ├── provider_custom.go      # Адаптер кастомных LRCLIB/lrcmux URL
│   │   ├── engine.go               # Диспетчер провайдеров и дедупликация
│   │   ├── response_subsonic.go    # Ответы getLyrics (XML/JSON)
│   │   ├── response_opensubsonic.go# Ответы getLyricsBySongId (XML/JSON)
│   │   ├── endpoint_handler.go     # LRCLIB-совместимый API (/lyrics/api/get)
│   │   └── debug_handler.go        # Диагностика /_smart/lyrics/test
│   ├── search/
│   │   ├── layout.go               # Двунаправленный маппер QWERTY <-> ЙЦУКЕН
│   │   ├── phonetic_rules.go       # Музыкальные алиасы и фонетические правила
│   │   ├── translit.go             # Транслитерация RU <-> EN и дедупликация согласных
│   │   ├── levenshtein.go          # Расстояние Дамерау-Левенштейна
│   │   ├── trie.go                 # Префиксное дерево Trie для автокомплита
│   │   ├── dictionary.go           # Потокобезопасный словарь и ранжирование
│   │   ├── engine.go               # Конвейер умного анализа запросов
│   │   └── search_test.go          # Комплексные юнит-тесты поиска
│   ├── db/
│   │   ├── sqlite.go               # Подключение к SQLite (modernc.org/sqlite, WAL)
│   │   ├── loader.go               # Чтение исполнителей, альбомов и треков
│   │   ├── enricher.go             # Фоновое обогащение full_text в SQLite
│   │   └── db_test.go              # Тесты работы с БД и обогащения
│   └── proxy/
│       ├── proxy.go                # HTTP Reverse Proxy и роутер
│       ├── interceptor.go          # Перехватчик Subsonic и Native UI эндпоинтов
│       ├── interceptor_lyrics.go   # Перехватчик Subsonic / OpenSubsonic текстов
│       ├── fanout.go               # Параллельный fan-out к Navidrome
│       ├── merge_json.go           # Слияние и дедупликация JSON Subsonic ответов
│       ├── merge_xml.go            # Слияние и дедупликация XML Subsonic ответов
│       ├── debug_handler.go        # Эндпоинт /_smart/test для отладки
│       └── proxy_test.go           # Тесты слияния ответов и диагностического API
├── Dockerfile                      # Многоэтапный минимальный образ (< 20MB)
├── docker-compose.yml              # Совместное развертывание с Navidrome
└── go.mod
```
