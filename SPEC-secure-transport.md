# poisq Secure Transport

## Цель

Приложение poisq шифрует весь свой трафик до poisq Studio так, что CDN и остальные посредники не видят логины, пароли, токены, запросы и ответы. Navidrome остаётся источником учётных записей и прав. Стандартные Subsonic-клиенты продолжают работать без шифрования. Публичный вход Studio принимает только Subsonic и защищённый протокол; веб-интерфейсы Navidrome и Studio через него недоступны.

Требования по приоритету: безопасность и корректность, надёжность на мобильной сети и через CDN, минимальный расход батареи и трафика клиента, простота реализации на стандартных библиотеках.

## Архитектура и границы доверия

- **poisq Studio** — вся серверная часть: публичный Subsonic-прокси `:4534` (умный поиск, расширения poisq, трансляция) и панель управления `:4535`.
- Маршрут из интернета: приложение → TurboFlare → NPM → FRP → Studio `:4534` → Navidrome. CDN нужен против блокировок: его адреса в белых списках. CDN завершает внешний TLS сам; TLS passthrough и WebSocket Upgrade на этом маршруте не работают. Испытания подтвердили бинарный HTTPS POST и потоковые ответы длительностью 150 секунд.
- **CDN, NPM и FRP считаются посредниками, которые видят весь HTTP.** Им доступны адрес, путь, заголовки, объём, время и сетевые ошибки. Шифрование не защищает от блокировки и отказа в обслуживании.
- Studio и Navidrome работают в одной docker-сети на одном хосте; трафик между ними не шифруется.
- **FRP пробрасывает только `:4534`.** Navidrome `:4533` и панель Studio `:4535` доступны только из домашней сети или через Tailscale и аналоги. Это обязательное правило развёртывания; Studio не определяет источник запроса по IP, потому что через FRP все внешние запросы приходят с локального адреса.
- Политика `:4534` одинакова для всех источников запросов: из дома, через CDN или через VPN.

## Возможности и порядок реализации

| Шаг | Модуль | Ответственность | Зависимости |
|---|---|---|---|
| 0 | `navidrome-web-guard` | `:4534` пропускает только Subsonic; веб-интерфейс Navidrome закрыт по умолчанию | — |
| 1 | `secure-pairing` | Ключи установки, сертификат рабочего ключа, QR v1, разбор и закрепление в приложении | — |
| 2 | `secure-channel` | Handshake, сессии, независимые зашифрованные запросы, записи ответа, защита от повторов, лимиты | `secure-pairing` |
| 3 | `secure-sign-in` | Вход по каналу, токены устройств, отзыв, изоляция профилей | `secure-channel` |
| 4 | `secure-subsonic` | Канал → существующий обработчик прокси, список разрешённых методов, все сетевые пути приложения | `secure-sign-in` |
| 5 | `secure-playback` | Аудио кусками, seek, подгрузка следующего трека, gapless, фон, CarPlay | `secure-subsonic` |
| 6 | `secure-downloads` | Офлайн-загрузки фоновым `URLSession` с зашифрованными файлами | `secure-subsonic` |
| 7 | `secure-policy` | Флаг аккаунта и режим установки «только защищённый вход» | `secure-sign-in` |

Шаг 0 не зависит от остальных и выполняется первым. Перед шагом 2 делается межъязыковой прототип: handshake Go↔Swift, несколько параллельных запросов и перемотка через реальный маршрут CDN. По его итогам фиксируются лимиты и формат на проводе. Функция включается после проверки всех сетевых путей защищённого профиля.

Сервис в разработке, внешних пользователей нет: обратная совместимость с прежними профилями и миграция не требуются. Разовое действие при включении: сменить пароли Navidrome, потому что прежние Subsonic-токены передавались в URL через CDN.

## Шаг 0. Веб-интерфейс Navidrome

- Настройка Studio «Закрыть веб-интерфейс Navidrome» **включена по умолчанию**. Если настройку не удалось прочитать, интерфейс считается закрытым.
- Когда настройка включена, `:4534` обслуживает только список разрешённого: `/rest/*` (Subsonic, OpenSubsonic, расширения poisq и трансляция) и, после шага 2, префикс защищённого протокола. Остальные пути получают 404 без обращения к Navidrome. Новые пути будущих версий Navidrome автоматически остаются закрытыми.
- Фильтр проверяет нормализованный путь, и в Navidrome уходит именно он. Запросы с неоднозначным путём (`..`, `.`, повторные `/`, закодированные `/`, `\` и точки, нарушения регистра префикса) отклоняются, а не исправляются.
- Публичные ссылки Navidrome `/share` закрыты вместе с интерфейсом. Отдельное разрешение для них — возможное расширение, по умолчанию выключено.
- Клиенты, работающие через собственное API Navidrome, переключаются на режим Subsonic. Панель Navidrome открывается напрямую на `:4533`.

## Профили приложения

- Режим выбирается для каждого профиля при добавлении сервера. QR отсканирован — защищённый профиль, весь трафик этого профиля шифруется в любой сети, включая домашнюю. Без QR создаётся обычный Subsonic-профиль без шифрования, совместимый с любым Subsonic-сервером.
- Сканирование доступно в существующей форме входа через «Дополнительно → Сканировать QR poisq». Сканирование заполняет адрес, выбирает защищённый режим и запускает проверку канала. Поля и расположение основной формы сохраняются; проверка и ошибки показываются в существующей зоне состояния.
- После сканирования форма показывает хост и короткий отпечаток корневого ключа.
- Если для уже известного адреса QR содержит другой корневой ключ, ключ не заменяется молча. Приложение показывает предупреждение о возможной подмене; замена возможна только явным действием и удаляет сессии, токен устройства и загрузки старого профиля.
- На адрес существующего защищённого профиля нельзя создать обычный профиль; проверка выполняется до любого сетевого запроса с учётными данными. Обычный профиль на другой адрес, например домашний, создаётся свободно.
- «Войти» активна, когда поля заполнены и канал именно этого профиля подтверждён. Обработчик входа, включая отправку с клавиатуры, сам проверяет, что подтверждённая сессия ещё действительна. Истечение сессии, смена адреса и потеря соединения возвращают форму к проверке.
- Защищённый профиль не переходит в обычный режим из-за ошибки, редиректа или другого адреса. Автопереключение на запасные адреса для защищённого профиля отключено. Редиректы в защищённых запросах, включая фоновую сессию, не выполняются.
- Профили изолированы по установке и учётной записи: адрес, закреплённый ключ, сертификат, токен устройства в Keychain, сессии, кеш, фоновые задачи и загрузки. Отключить шифрование можно только созданием обычного профиля на другой адрес.
- Подсказка «сервер поддерживает защищённое соединение» из расширения OpenSubsonic `poisq` допустима для обычного профиля, но никогда не переключает режим и не устанавливает доверие к ключу: ключ закрепляется только через QR.

## Ключи и ротация

| Ключ | Назначение | Срок | Смена |
|---|---|---|---|
| Корневой Ed25519 | Открытая часть в QR, подписывает сертификаты рабочего ключа | Годы | Перевыпуск QR по доверенному маршруту или предварительная ротация |
| Рабочий X25519 | Статический ключ сервера в handshake | Сертификат 7 дней | Автоматически |
| Сессионные | Шифрование запросов | До 24 часов | Эфемерные; обновление внутри сессии |

- Ключи генерируются стандартными реализациями и хранятся в отдельных файлах с правами `0600` рядом с базой Studio. В репозитории секретов нет; в журналы ключи и их части не попадают.
- **Сертификат рабочего ключа**: версия, `installation_id`, эпоха (u32, монотонная), открытый ключ X25519, `not_before`, `not_after`, SHA-256 следующего корневого ключа, подпись корневым ключом. Сертификат публичный и отдаётся без авторизации; подделать его без корневого ключа нельзя.
- Новый рабочий ключ выпускается за 3 дня до истечения текущего. Сервер принимает обе эпохи до истечения старой. Клиент кеширует сертификат и не запрашивает его отдельно при каждом handshake. На неизвестную или устаревшую эпоху сервер отвечает актуальным сертификатом, клиент проверяет его и повторяет handshake.
- Клиент проверяет подпись, `installation_id` из QR и монотонность эпохи: эпоха меньше уже принятой отвергается. Сроки действия проверяются с допуском на расхождение часов телефона; основой защиты от отката служит эпоха.
- Компрометация рабочего ключа устраняется выпуском новой эпохи и отказом от старой; QR не меняется. Посредник с украденным рабочим ключом может выдавать себя за сервер не дольше срока сертификата.
- **Предварительная ротация корня**: при генерации корня Studio создаёт и следующий корневой ключ; в сертификатах публикуется только его хэш. Администратору предлагается вынести следующий ключ из Studio в резервную копию. Запись ротации подписана новым корнем, и клиент принимает её только если хэш нового корня совпадает с ранее принятым обязательством. Так корень меняется без пересканирования QR, а тот, кто украл текущий корень, не может перехватить ротацию.
- Если и текущий, и следующий корень скомпрометированы, единственный путь — новый QR по доверенному маршруту. Взлом самого Studio раскрывает ключи, хранящиеся на сервере; двухуровневая схема обеспечивает плановую ротацию, но не защищает от компрометации хоста.

## Формат QR v1

Текст `poisq-secure:v1:<installation-id>:<root-public-key>:<public-origin>`. Компоненты после версии разделены двоеточиями.

- `installation-id` — 16 случайных байтов, 32 строчных шестнадцатеричных символа.
- `root-public-key` — 32 байта открытого ключа Ed25519 в Base64URL без padding.
- `public-origin` — канонический HTTPS origin в Base64URL без padding, например `https://teedi.ru`. Домен в ASCII, IDN передаётся в Punycode. Порт необязателен, явный 443 удаляется. Путь, userinfo, query и fragment запрещены. Studio принимает корневой завершающий слеш и нормализует регистр; приложение принимает только каноническое представление.
- Максимальная длина токена 512 байт. Неизвестная версия или некорректный QR оставляют форму без изменений.
- QR общий для всех пользователей и устройств установки, не содержит учётных данных и секретов. Внешний адрес задаётся в настройках Studio и не извлекается из заголовков запроса. QR показывается в панели Studio, доступной только из домашней сети или VPN. Одноразовые приглашения в v1 не входят.

## Канал

Примитивы: X25519, Ed25519, HKDF-SHA256, AES-256-GCM. На iOS — CryptoKit, в Go — стандартная библиотека. Сторонние криптобиблиотеки не используются.

### Handshake

- Шаблон `Noise_NK_25519_AESGCM_SHA256` строго по спецификации Noise; статический ключ ответчика — рабочий ключ из сертификата. Реализация на обеих сторонах проверяется официальными тестовыми векторами Noise и общим межъязыковым вектором poisq.
- Prologue: `poisq-secure/v1`, `installation_id`, эпоха рабочего ключа. Подмена версии, установки или эпохи ломает handshake.
- `POST <prefix>/hello`: первое сообщение (`e, es`) без полезных данных приложения. Сервер не выполняет никаких действий по содержимому первого сообщения, кроме ответа: оно повторяемо и не обладает прямой секретностью.
- Ответ (`e, ee`) содержит `session_id` (128 случайных битов), срок жизни, ограничения и подтверждает, что сервер владеет рабочим ключом. Прямая секретность обеспечивается DH между эфемерными ключами.
- `Split()` даёт два корневых ключа сессии, по одному на направление.
- `GET <prefix>/certificate` отдаёт текущий сертификат рабочего ключа без авторизации. Клиент получает его, только когда кешированного нет или он истёк.
- Префикс протокола — `/poisq-secure/v1/`; эти запросы обслуживает сам Studio и не передаёт в Navidrome.

### Формат на проводе (v1)

Все числа big-endian. Реализация: `internal/securetransport/channel.go` и `PoisqCore/SecureChannelWire.swift`; побайтное совпадение закреплено вектором `testdata/channel-v1.json`.

| Сообщение | Состав |
|---|---|
| `hello` | `version u8 = 1` · `epoch u32` · Noise message 1 (48 байт) — ровно 53 байта |
| ответ `hello` | Noise message 2 с нагрузкой `session_id [16]` · `ttl u32` · `maxRequest u32` · `maxRecord u32` |
| `call` | `version u8` · `session_id [16]` · `counter u64` · AES-GCM(запрос) |
| ответ `call` | записи: `frame u32` (младшие 31 бит — длина шифротекста, старший — последняя запись) · AES-GCM(часть ответа) |

- Ключ запроса — `HMAC-SHA256(корень c→s, "poisq-secure/v1 request" ‖ counter)`, ключ ответа — `HMAC-SHA256(корень s→c, "poisq-secure/v1 response" ‖ counter)`. Nonce — 32 нулевых бита и индекс записи (у запроса 0). AAD — заголовок запроса ‖ индекс u64 ‖ признак последней записи u8.
- Внутри канала: запрос `op u8 · тело`, ответ `status u8 · тело`. Шаг 2 реализует проверочный обмен `op = 0x01` (эхо); вход и Subsonic добавляют свои операции.
- Коды, видимые посредникам: 404 — функция выключена или путь неизвестен; 400 — некорректный или неподлинный запрос, повтор счётчика; 409 — неизвестная эпоха, тело — актуальный сертификат; 410 — сессия неизвестна или истекла (повтор безопасен: сервер отвергает такой запрос до расшифровки); 413 — слишком большое тело; 429 — превышена частота handshake; 503 — таблица сессий заполнена.

### Запросы и ответы

- `POST <prefix>/call`. Открытый заголовок: версия, `session_id`, `counter` (u64). Каждый запрос и ответ шифруется собственным ключом, выведенным из корня своего направления и счётчика; сами корни ничего не шифруют.
- Запросы независимы: допускаются параллельные запросы, запросы не по порядку и повтор операции чтения. Медиа и API не блокируют друг друга, перемотка не требует нового handshake.
- Ответ состоит из записей по 16 КиБ (начальное значение). Nonce записи — её индекс. В AAD входят заголовок запроса, индекс записи и признак последней записи; усечение ответа обнаруживается.
- Счётчик клиента выдаётся синхронно из состояния actor и общий для всех запросов сессии; параллельные запросы, ожидающие один handshake, никогда не получают одинаковый счётчик. **Сессия не сохраняется на диск**: после перезапуска приложения выполняется новый handshake, поэтому пара ключ/nonce не повторяется.
- Сервер хранит для каждой сессии окно принятых счётчиков (битовая карта на 4096 значений). Повтор и слишком старый счётчик отвергаются. Окно отмечается только после успешной расшифровки, поэтому поддельные запросы не «сжигают» счётчики клиента.
- Повтор чтения выполняется с новым счётчиком. Изменяющие операции несут ключ идемпотентности, который сервер хранит в пределах сессии; повтор не выполняет действие дважды.
- Отдельное обновление ключей сессии не нужно: каждый запрос получает свой ключ, а корни сессии живут не дольше 24 часов. После пробуждения приложения сессия продолжает работать без сетевых обменов.
- На «сессия неизвестна» (перезапуск Studio, истечение) клиент выполняет один новый handshake и прозрачно повторяет запрос чтения.
- Ошибки, видимые посредникам, сводятся к минимальному набору кодов без подробностей. Детали ошибок передаются внутри канала.

### Лимиты

Начальные значения, уточняются по прототипу:

| Параметр | Значение |
|---|---|
| Тело `hello` | ровно 53 Б |
| Тело `call` | ≤ 64 КиБ |
| Сессия до входа | 2 минуты, разрешён только вход |
| Сессия после входа | 24 часа |
| Сессий на токен устройства | 8 |
| Сессий на установку | 1024 |
| Частота `hello` | 20 в минуту на IP (token bucket, до 4096 адресов) |
| Частота попыток входа | Ограничение по IP и по аккаунту (шаг 3) |

- Реальный IP клиента берётся из заголовка, который выставляет NPM, и только если непосредственный пир — адрес FRP-клиента из настроенного списка доверенных прокси. NPM перезаписывает, а не дополняет эти заголовки. IP используется только для лимитов.
- Тело запроса ограничивается до расшифровки; разбор выполняется только после успешной аутентификации записи.

## Вход и токены устройств

- Логин и пароль передаются только внутри подтверждённой сессии и один раз. Studio проверяет их через Navidrome (`/rest/ping` с токен-авторизацией Subsonic) и выдаёт **токен устройства** (32 случайных байта).
- Операции канала: `0x02` вход (`u8 len · имя · u16 len · пароль · u8 len · имя устройства`), `0x03` продолжение по токену (`токен [32]`), `0x04` выход — отзыв устройства этой сессии. Ответ на вход и продолжение: `status · новый токен [32] · ID устройства [16] · срок сессии u32`. Статусы: `0x02` операция запрещена в этой сессии, `0x04` неверное имя или пароль, `0x05` превышена частота, `0x06` Navidrome недоступен, `0x07` слишком много устройств, `0x08` устройство отозвано — нужен вход заново. До входа любые операции, кроме проверки, входа и продолжения, отвечают `0x02`; вход в уже вошедшей сессии тоже запрещён.
- Таблица `secure_devices` в `poisq.db` хранит SHA-256 текущего и предыдущего токена, пользователя, имя устройства, время входа и активности. Токен меняется при каждом продолжении. Предыдущий токен принимается ещё 2 минуты от момента замены (ответ мог потеряться); повторное предъявление окно не продлевает. Позже заменённый токен считается украденным: устройство удаляется, его сессии завершаются.
- Пароль Navidrome сверяется до замены токена: если Navidrome недоступен, токен остаётся прежним и клиент повторит позже. Ответ «неверный пароль» (код 40) означает смену пароля или удаление пользователя: все его устройства отзываются.
- **Решение по доступу к Navidrome.** Studio хранит пароль Navidrome для каждого устройства, зашифрованный существующим `security.KeyCipher`, и удаляет его вместе с устройством. Вход в Navidrome по заголовку `Remote-User` отвергнут: через FRP пиром любого внешнего запроса выглядит доверенный локальный адрес, и подделанный заголовок дал бы войти под любым пользователем. Navidrome сам хранит пароли в обратимом виде, поэтому хранение в Studio почти не увеличивает ущерб от взлома хоста. В памяти пароль живёт только в сессии после входа.
- Сессия после входа живёт 24 часа; у одного устройства не больше 8 сессий, лишние вытесняются начиная с самой старой. У аккаунта не больше 32 устройств.
- Попытки входа: 10 за 15 минут на аккаунт (без учёта регистра) и 30 за 15 минут на адрес; продолжение по токену ограничено по адресу.
- Отзыв: список устройств с отзывом в панели Studio (Настройки → Secure Transport). Отзыв сразу завершает сессии устройства.
- Клиент (`SecureChannel`) сохраняет новый токен до его использования через `SecureCredentialStore`, сам продолжает сессию по токену после нового handshake, удаляет отозванный токен и выполняет вход и продолжение не больше чем одним запросом одновременно. В приложении токен хранится в Keychain с `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`: он доступен фоновому воспроизведению после первой разблокировки и не попадает в резервные копии.
- Шаг 3 разделён: серверная часть, протокол и клиентская логика готовы; форма входа со сканированием QR, профиль и хранилище в Keychain — следующая часть шага.

## Subsonic через канал

- Внутри канала передаётся Subsonic-запрос: метод и параметры. Studio проверяет метод по явному списку разрешённых, добавляет авторизацию пользователя на стороне сервера и передаёт запрос **в существующий обработчик прокси внутри процесса**, без сети. Умный поиск, слияние ответов и расширения poisq работают без отдельной реализации.
- Произвольные пути, методы HTTP, заголовки и редиректы во внутренние сервисы не проходят. Административные методы Subsonic (управление пользователями, сканирование) через канал в v1 запрещены.
- Каждый медиаресурс выдаётся только через Navidrome от имени пользователя: права на библиотеку и операцию проверяет Navidrome. Прямое чтение файлов из медиатеки в обход проверки прав запрещено.
- Защищённый профиль использует канал для всех путей к Studio: вход, API, обложки, кеш, тексты, биографии, предзагрузка, аудио, загрузки и команды трансляции.
- Виджеты, Now Playing и CarPlay берут изображения только из общего кеша App Group и не обращаются к сети с данными профиля.
- Трансляция в Music Assistant: команды идут через канал, ссылку для колонки Studio строит внутри домашней сети. Ссылка с учётными данными не покидает Studio.
- Сторонние URL из ответов (интернет-радио, внешние изображения) не открываются с данными профиля и не проходят через канал.
- Журналы Studio не содержат логинов, паролей, токенов, ключей и содержимого запросов и ответов; `session_id` пишется только усечённым.

## Воспроизведение и подгрузка

- Аудио передаётся в исходных байтах без Base64 и перекодирования. После проверки записей данные подаются плееру через собственный источник данных AudioStreaming.
- Аудио запрашивается кусками по 4 МиБ (начальное значение), 2–3 запроса параллельно. Перемотка — запрос куска с нужного смещения; устаревшие запросы отменяются. Обрыв со стороны CDN — обычный повтор чтения.
- Подгрузка следующего трека выполняется внутри процесса по тому же каналу, пока идёт воспроизведение (аудиосессия активна). Фоновый `URLSession` для неё не используется.
- **Открытый вопрос шага 5**: поддерживает ли AudioStreaming собственный источник данных для элементов очереди и gapless, а не только URL. Проверяется первым в прототипе воспроизведения.
- CDN-кеш, каталог шифрованных треков и постоянные медиа-ключи для онлайн-воспроизведения в архитектуру не входят.

## Офлайн-загрузки

- Загрузка идёт фоновым `URLSession` и продолжается, когда приложение приостановлено или выгружено.
- По каналу клиент получает для трека: токен загрузки, ключ файла, версию файла, размер и размер куска. Ключ файла передаётся только внутри канала.
- `GET <prefix>/blob/<token>` отдаёт файл, зашифрованный на лету кусками по 64 КиБ AES-256-GCM. Nonce куска — его индекс; в AAD входят токен, индекс, общее число кусков и признак последнего куска. Поддерживается Range для докачки. Ответ помечается `Cache-Control: no-store`.
- Ключ файла выводится из секрета Studio, токена и **версии файла** (хэш содержимого или размер и время изменения). Если файл на сервере изменился, например после правки тегов, сервер отвечает 409 и ничего не шифрует; клиент запрашивает новый токен. Шифрование другого содержимого той же парой ключ/nonce исключено.
- Токен загрузки запечатан секретом Studio, действует до 7 дней, привязан к устройству, треку и версии файла и отзывается вместе с токеном устройства. Сам по себе токен даёт только шифротекст.
- Клиент расшифровывает файл один раз в обработчике завершения загрузки, проверяет все куски и их число, сохраняет открытый файл под защитой данных iOS и исключает его из резервных копий. При любой ошибке проверки файл удаляется и загрузка помечается неудачной.
- Ключи и токены загрузок принадлежат профилю и удаляются вместе с ним.

## Политика доступа на сервере

- По умолчанию `:4534` принимает обычный Subsonic и защищённый протокол. Выбор клиента не ограничивает сервер.
- Флаг аккаунта «только защищённый вход»: Studio отклоняет для этого пользователя обычные Subsonic-запросы на `:4534`. Сторонний клиент такого пользователя подключается к Navidrome напрямую в домашней сети.
- Режим установки «только защищённый вход» применяет то же ко всем аккаунтам.
- Выключение Secure Transport прекращает приём новых защищённых запросов и завершает активные сессии; токены устройств сохраняются до явного отзыва. По умолчанию Secure Transport выключен.

## Энергопотребление клиента

- Основной расход батареи — радиомодуль, а не криптография: AES-GCM аппаратно ускорен, X25519 стоит десятки микросекунд.
- Медиа скачивается пачками, после чего радио простаивает. Один handshake на сессию; восстановление после фона без сетевых обменов.
- Все запросы идут через одно соединение URLSession с CDN (HTTP/2 или HTTP/3 — проверяется на прототипе).
- В Low Data Mode, режиме энергосбережения и на сотовой сети объём подгрузки уменьшается.
- Бинарный формат без Base64 и лишних копирований.

## Остаточные риски

- По размерам и времени запросов посредник может угадать трек. Последний кусок ответа дополняется до фиксированного размера; полная защита от анализа трафика не входит в v1.
- Блокировка и отказ в обслуживании не устраняются шифрованием.
- Взлом хоста Studio или устройства пользователя выходит за пределы защиты канала.
- Обычный Subsonic-трафик сторонних клиентов через CDN передаётся без шифрования приложения; это осознанный риск их пользователей.

## Проверка

1. Фильтр `:4534`: разрешённые пути проходят, остальные получают 404 без обращения к Navidrome; обходы `//app`, `/rest/../app`, `/rest/%2e%2e/app`, `%2F`, `\`, `/REST/` отклоняются; настройка по умолчанию включена, ошибка чтения закрывает интерфейс.
2. Go генерирует QR и сертификат, Swift читает те же векторы. Разбор отвергает неизвестные версии, некорректные ключи, адреса с лишними компонентами, чужой `installation_id`, неверную подпись и откат эпохи.
3. Handshake проходит официальные векторы Noise и межъязыковой вектор poisq. Подменённый ключ или сбой handshake останавливают вход до отправки учётных данных. Кнопка, отправка с клавиатуры и устаревшая сессия покрыты одинаковым ограничением.
4. Канал: подмена, повтор, перестановка, усечение записей, повтор счётчика, неверная идентичность, редирект, неизвестная сессия, смена сети; параллельные запросы и идемпотентность изменяющих операций.
5. Перехватывающий тестовый прокси подтверждает отсутствие открытых данных во внешнем HTTP для всех сетевых путей защищённого профиля, включая обложки, загрузки и трансляцию.
6. Токены устройств: обновление, обнаружение повторного использования, отзыв из панели, отзыв при смене пароля и удалении пользователя в Navidrome.
7. Изоляция: два сервера, два аккаунта на одном сервере, два устройства одного аккаунта — независимые сессии, права медиатек, кеш, фоновые задачи и Keychain. Запрос чужого трека через канал отклоняется.
8. Загрузки: докачка через Range, истёкший токен, 409 после изменения файла, повреждённый кусок, усечённый файл, удаление профиля.
9. На iPhone: побитовое сравнение FLAC, seek, gapless, блокировка экрана, фон, CarPlay, офлайн. Время до первого проверенного блока, старта и seek, память, доля повторов и энергопотребление в сравнении с обычным профилем в той же сети.
10. Изменения протокола требуют нового вектора совместимости; старая версия обрабатывается с отказом (fail-closed).

## Размещение кода

- Go: фильтр — в `internal/proxy`; протокол, ключи и сертификаты — в `internal/securetransport`; подключение через существующую конфигурацию сервера. Настройки — в панели Studio (Настройки → Secure Transport).
- Ключи установки создаются при первом включении в папке `secure-transport` рядом с `poisq.db` и сохраняются при выключении, поэтому QR не меняется. Ротация рабочего ключа проверяется при запуске и каждый час.
- QR рисуется на сервере в SVG из модулей кода (`rsc.io/qr`, без внешних зависимостей и сетевых обращений) и отдаётся только панелью Studio.
- Swift: контракт, QR, сертификат и канал — в `PoisqCore`; источник аудиоданных — в `PoisqPlayback`; форма входа, загрузки и кеш — в приложении iOS.

```sh
go test -count=1 ./internal/proxy ./internal/securetransport
go test -count=1 ./...
go build -o /tmp/poisq-secure-transport-check ./cmd/proxy
swift test --package-path app/ios/PoisqKit --filter "Secure|Noise"
git diff --check
```
