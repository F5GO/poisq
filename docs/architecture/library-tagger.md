# Аудит медиатеки, обложки и теггер

Подсистемы `internal/metadata` и `internal/tagger` следят за чистотой тегов и обложек фонотеки. Все изменения сначала попадают в безопасный **Staging-буфер** (`staging_changes`), и ни один файл в `/music` не изменяется до явного подтверждения пользователя в Studio.

## Синхронизация и дедупликация (`folder_scanner.go`)

Метод `LibraryScanner.SyncFromNavidromeDB` вызывается при старте и периодически каждые `SYNC_INTERVAL` (`2m`):

1. Читает все записи из `navidrome.db` (`media_file`), разделяя основной каталог и папки-копии (`IsCopyPath` распознаёт суффиксы `- копия`, `— копия`, `(копия)`, `_copy`, `(1)`).
2. Дедуплицирует треки на лету по `TrackDedupKey(artist, title, durationBucket)` с приоритетом основного каталога над копиями (уникальные треки из папок-копий сохраняются).
3. Проверяет локальную обложку папки (`InspectFolderCover`) и наличие файла `.lrc` рядом с аудио.
4. Проверяет `artist`, `title`, `album` на битую кодировку CP1251 (`DetectAndFixMojibake`) и при обнаружении сразу создаёт Staging-предложение (`change_type="mojibake"`, `confidence=98`).
5. Нормализует macOS NFD-последовательности (`и+̆ → й`, `е+̈ → ё`), записывает треки батчами по 500 и запускает `TrackRepository.DeduplicateTracks()` для очистки дубликатов (с ранжированием по наличию не-копии, `verified`/`synced` текста, отсутствию mojibake и разрешению обложки).

## Исправление кодировки CP1251 (`mojibake_fixer.go`)

Детектор работает без внешних библиотек по встроенной таблице CP1251 → Unicode и распознаёт два класса повреждений:
- **Форма Б (сырые байты CP1251 в невалидном UTF-8)** — фиксируется при `≥ 3` старших байтах и валидной структуре русских слов (наличие и гласных, и согласных).
- **Форма А (CP1251, прочитанный как Latin-1 и сохранённый в UTF-8)** — чтобы не портить западную диакритику (`Björk`, `Motörhead`), требует отсутствия кириллицы, минимум 3 символов из диапазона `0xC0..0xFF`/`0xA8`/`0xB8`, их долю `≥ 50%` от всех букв и валидную кириллическую структуру после декодирования.

## Глубокий аудит MusicBrainz и правило Folder-as-Album Lock

Глубокий аудит (`RunDeepAudit` / `RunTrackAudit`) запускается из Studio и проверяет папки (пропуская `IsCopyPath`):

- **Folder-as-Album Lock (`ComputeFolderAlbumLock`)**: если в папке `≥ 2` треков и минимум у половины есть номер трека или доминирующий альбом, папка считается цельным альбомом — аудит удерживает единое название альбома и не «разрывает» его на синглы.
- **MusicBrainz (`musicbrainz_client.go`)**: запросы к `https://musicbrainz.org/ws/2` идут через `ResilientClient` с ограничением 1 запрос / `1100ms`. При `Score ≥ 85` создаются предложения `musicbrainz` (канонический артист, альбом, год, MBID) либо fallback `artist_canonical`.

## Поиск, извлечение и фильтрация обложек

### Поиск локальной обложки (`cover_locator.go`, `embedded_cover.go`, `image_reader.go`)
1. `FindCoverAnywhere` ищет файлы с приоритетными именами (`cover`, `folder`, `front`, `album`, `art`, `artist`, `default`, `thumb`) с расширениями `.jpg`/`.jpeg`/`.png`/`.webp` в папке трека, подпапках (`artwork`, `scans`, `covers`, `images`), дочерних и до 3 родительских папок (не выходя за `MUSIC_PATH`), с нечётким резолвингом путей (`ResolveFuzzyDirectory`).
2. Если файла нет — `ExtractCoverFromAudioFile` читает встроенную обложку: нативным парсером ID3v2 (`PIC`/`APIC`, до 30 МБ) для MP3, нативным парсером блока `PICTURE` для FLAC и через `ffmpeg` (таймаут `10s`) для остальных форматов.
3. Размеры определяются через `image.DecodeConfig` с ручным парсером заголовков WebP (`VP8`/`VP8L`/`VP8X`), PNG и JPEG (`SOF`).

### Подбор High-Res обложек (`cover_fetcher.go`, `cover_filter.go`, `scanner_arbiter.go`)
Если локальной обложки нет или её разрешение ниже `1200×1200`, аудит ищет кандидатов:
1. **Cover Art Archive** (`HEAD https://coverartarchive.org/release/<mbid>/front-1200`, оценка `95`).
2. **Apple Music / iTunes Search API** (`limit=15`, до 3 запросов), с подменой превью `100x100bb → 3000x3000bb`.
3. **Фильтрация (`cover_filter.go`)**: 35+ стоп-слов (`karaoke`, `караоке`, `tribute`, `instrumental`, `минусовка`, `soundalike`, `sing2piano`, `karafun` и др.) отсекают мусорные сборники; для не-сборников обязателен матч артиста, порог скоринга `≥ 40`.
4. **AI-арбитраж спорных папок (`scanner_arbiter.go`, `ai.MetadataArbiter`)**: для папок из `1–2` треков, папок с разделителем ` - ` в имени или синглов (`Title == Album`) LLM определяет канонический альбом и точный запрос `CoverSearchTerm` для iTunes.
5. Предложение в Staging создаётся только если найденная обложка строго крупнее текущей.

При сохранении обложки (`DownloadAndSaveAtomically`) URL проверяется на SSRF (запрет локальных/приватных IP, включая редиректы до 5 переходов), скачивается до `15 МБ`, валидируется как изображение и атомарно записывается в `cover.jpg`.

## Атомарный теггер и откат (`internal/tagger`)

Запись тегов выполняется через CLI **`ffmpeg`** с копированием аудиопотока без перекодирования (`-map 0 -c copy -map_metadata 0`, таймаут `30s`).

- **Поддерживаемые форматы для записи**: **FLAC, MP3, M4A, OGG, OPUS** (пересечение `allowedWriteExts` и `allowedAudioExts`).
- **Особенности форматов**:
  - **MP3**: принудительно ID3v2.4 без ID3v1 (`-id3v2_version 4 -write_id3v1 0`).
  - **FLAC / OGG / OPUS**: дополнительно пишется `ORIGINALDATE` при `Year > 1900`.
- **Маппинг Picard (`picard_mapper.go`)**: помимо базовых `artist`, `album`, `album_artist`, `title`, `date`, `track`, записываются парные теги MusicBrainz (`MUSICBRAINZ_ALBUMID` + `MusicBrainz Album Id`, `MUSICBRAINZ_ARTISTID` + `MusicBrainz Artist Id`, `MUSICBRAINZ_TRACKID` + `MusicBrainz Release Track Id`).

### Двойная проверка целостности (`atomic_tag_writer.go`, `tag_reader.go`)
1. Временный файл `.poisq_tmp_*<ext>` создаётся в той же папке; его размер должен быть `> 0` и `≥ 95%` исходного.
2. **FLAC Bit-Perfect**: до и после работы `ffmpeg` из заголовка `STREAMINFO` (байты `26..42`) извлекается 16-байтный MD5 несжатого PCM-аудиопотока. При малейшем расхождении временный файл удаляется, а оригинал остаётся нетронутым.
3. Только после прохождения проверок восстанавливаются права файла и выполняется атомарный `os.Rename`.

### История и откат (`rollback.go`)
Перед применением любой правки тегов (включая ручное редактирование из Drawer трека, которое создаёт запись `change_type="manual"`) в `staging_changes.original_tags_json` сохраняется слепок исходных тегов. Операция **Undo** (`UndoProposal`) атомарно возвращает исходные теги и удаляет добавленные поля (`Clear`), переводя запись в статус `reverted`. Для `cover` откат меняет только статус записи в БД (файл `cover.jpg` на диске не удаляется).
