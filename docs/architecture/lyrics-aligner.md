# Тексты песен, турнир и Aligner

Подсистема поиска и синхронизации текстов (`internal/lyrics`, `internal/worker`, `internal/ai`, `internal/aligner`, `aligner/`) работает асинхронно через фоновую очередь и записывает готовые файлы `.lrc` атомарно рядом с аудиофайлами в `/music`.

## Провайдеры текстов

В `TournamentOrchestrator` подключены 4 провайдера (таймаут `6s`, допуск по длительности `6s`, у каждого свой `ProviderLimiter` и `CircuitBreaker`):

| Провайдер | Лимит / Breaker | Механизм получения | Форматы |
|---|---|---|---|
| **LRCLIB** (`lrclib.net`) | 4 конк. / `150ms`, breaker `4/3m` | Точный `GET /api/get` по вариантам артиста → fallback `GET /api/search`. | `lrc`, `plain`, `instrumental` |
| **Яндекс Музыка** (`api.music.yandex.net`) | 3 конк. / `250ms`, breaker `4/3m` | Поиск трека → при наличии OAuth-токена запрос `/tracks/{id}/lyrics?format=LRC` с подписью **HMAC-SHA256** (`timeStamp` + `sign`) → fallback на публичный `/tracks/{id}/supplement`. | `lrc`, `plain` |
| **NetEase Cloud Music** (`music.163.com/weapi`) | 3 конк. / `250ms`, breaker `3/3m` | Шифрованный `weapi` (двойной AES-128-CBC + RSA-1024 NoPadding): `/weapi/cloudsearch/pc` → `/weapi/song/lyric`. | `lrc`, `plain`, `instrumental` |
| **Genius** (`genius.com`) | 2 конк. / `300ms`, breaker `3/3m` | `/api/search/multi` → загрузка HTML (строго `https://*.genius.com`), извлечение `div[data-lyrics-container="true"]` и очистка мусора (`Contributors`, `Embed`). | `plain` |

## Скоринг кандидатов и турнир

### Скоринг (`internal/lyrics/matcher.go`)

Перед сравнением `CleanTitle` удаляет безопасные скобочные пометки издания (`deluxe`, `remastered`, `юбилейное`), но сохраняет и жёстко сверяет маркеры версий (`live`, `remix`, `acoustic`, `instrumental`, `slowed`, `reverb`, `минусовка`). При конфликте версий, несовпадении названия или расхождении длительности сверх допуска кандидат мгновенно отклоняется.

Для прошедших фильтр вычисляется итоговый балл по шкале `0..100` (порог принятия — **`60.0`**):

```text
Total = Title × 30 + Artist × 25 + SyncBonus × 25 + Duration × 15 + Album × 5 - CensoredPenalty
```

- `SyncBonus`: `1.0` для `lrc`/`instrumental`, `0.25` для `plain`.
- Слабое совпадение артиста (`0.4`) допускается только при точном совпадении длительности (`≤ 2.0s`).
- Цензурированный текст со звёздочками внутри слов получает штраф `-10`.
- Тексты-заглушки и обрезанные тексты (начинающиеся с `[Куплет 2]` без первого) отбрасываются `IsDefectiveLyrics`.

### Четыре фазы турнира (`internal/lyrics/tournament.go`)

Турнир опрашивает провайдеры параллельно и останавливается досрочно, как только найден полный `LRC`, подтверждённый консенсусом:

1. **Исходный запрос** (`artist`, `title`, `album`, `duration`).
2. **Локальные варианты** (`GenerateQueryVariants`, до 4): варианты написания артиста (`МакSим`/`MakSim`, транслит, `PrimaryArtist` без `feat.`) и очищенного названия.
3. **Discovery реального имени** (`discovery.go`, до 4): алиасы из MusicBrainz + поиск по одному названию и длительности (`±2s`) в LRCLIB, Яндексе и NetEase; спорные имена проверяет `LLMArtistJudge`.
4. **LLM-расширение запроса** (`LLMQueryExpander`, до 3 вариантов, кэш в таблице `ai_alias_cache`).

### Кластерный консенсус (`internal/lyrics/consensus.go`)

Чтобы исключить попадание текста от другой песни, провайдеры голосуют (по 1 лучшему кандидату от провайдера, минимум 20 слов):
- Сходство текстов считается коэффициентом Дайса по мультимножеству слов.
- Два провайдера согласны при сходстве `≥ 0.80`; кластер считается подтверждённым при размере `≥ 2`.
- LRC признаётся полным (`IsFullLRC`), если содержит не менее `max(8, 0.7 × медианного числа строк)`, таймкоды монотонны, а последний таймкод лежит в диапазоне `[0.35 × duration, duration + 10s]`.
- Приоритет выбора: полный LRC из кластера → полный LRC близкой редакции (`sim ≥ 0.60`) → лучший plain-текст из кластера как эталон для акустического выравнивания.

## Очередь задач (`internal/worker/queue_processor.go`)

Фоновый воркер работает в **одну горутину**, проверяя очередь каждые `4s` (или сразу по `Wake()`) и обрабатывая до 5 задач за проход. При рестарте «зависшие» задачи `running` возвращаются в `pending` (`RequeueOrphaned`).

| Тип задачи (`job_type`) | Что выполняется |
|---|---|
| `tournament` | Только турнир провайдеров, без AI и выравнивания. |
| `ai_consensus` | Турнир + очистка/объединение LRC через LLM (`LyricsCleaner.BuildConsensus`). |
| `whisper_karaoke` | Принудительное акустическое выравнивание (если plain-текст уже есть, турнир пропускается). |
| `full_pipeline` *(по умолчанию)* | Турнир → при наличии LRC очистка LLM → иначе акустическое выравнивание (`poisq-aligner` или облачный режим). |

Обработка сбоев: до 3 попыток с квадратичным backoff (`15s`, `60s`), при исчерпании квот или кулдауне ключей задача переходит в `waiting_quota` без траты попыток. Все шаги пишутся в кольцевой буфер телеметрии (`JobTelemetryTracker`, до 200 задач) и в `lyrics_jobs.error_log`.

## Два режима создания караоке-таймингов

### 1. Локальный sidecar `poisq-aligner` (рекомендуемый)

Включается, когда задан `ALIGNER_URL` и для трека есть эталонный текст (`≥ 3` строк). При недоступности сервиса (`ErrUnavailable`) воркер автоматически откатывается на облачный режим.

Конвейер (`aligner/runner.py` → `tools/aligneval/aligneval.py`):
1. **Отделение вокала**: `Demucs` (`htdemucs`, `--two-stems=vocals`) + даунсемплинг в 16 кГц моно.
2. **Ансамбль ASR-якорей**: 6 прогонов Groq Whisper (`vocals`, `prompt`, `mix`, `chunks` по 40с, `turbo`, ускоренный `fast` `1.15×`), выравнивание Нидлмана–Вунша и медианное слияние.
3. **Оконный и контекстный проход `Qwen3-ForcedAligner-0.6B`**: уточнение границ строк в окнах `±1.5s` и с соседними строками (`ctx`).
4. **Независимый арбитр `MMS_FA` (`wav2vec2` CTC)**: проверяет те же контекстные окна; при расхождении `> 1.0s` берётся медиана оценок.
5. **Постобработка**: заполнение пропусков (`fill_gaps`), исправление растянутых стартов по RMS (`fix_stretched_starts`), подтяжка краёв к голосу и упреждение таймкодов на `ALIGNER_LEAD` (`0.5s`).

#### Оценка уверенности (`aligner/confidence.py`)

Для каждой строки рассчитывается уровень уверенности и сохраняется в таблицу `lrc_confidence`:

| Уровень | Основные условия |
|---|---|
| `high` | Строка найдена, расхождение с MMS `≤ 0.3s`, нет арбитражных конфликтов и растяжек. |
| `medium` | Расхождение с MMS `0.3..0.5s`, разброс оценок `> 0.8s`, сработал MMS-арбитраж, была правка растяжки или поддержка ASR `< 50%`. |
| `low` | Строка не найдена (оценена по соседям), выровнена вслепую (`filled`), расхождение с MMS `> 0.5s` (или `> 0.3s` для повторяющихся строк), либо нарушена монотонность. |

Если доля `low`-строк не превышает **`25%`** (`LowRatio <= 0.25`), трек получает статус `verified`; проблемные строки подсвечиваются в редакторе таймингов Studio.

### 2. Облачный режим (`Groq Whisper` + Нидлман–Вунш)

Работает, если `ALIGNER_URL` не задан (или `poisq-aligner` недоступен):
1. `AudioTranscoder` сжимает трек через `ffmpeg` в память (моно 16 кГц, Opus 32 кбит/с, полосовой фильтр `100–7500 Гц`, лимит `15 МиБ`).
2. `GroqWhisperClient` получает пословные таймкоды (`whisper-large-v3`, fallback `whisper-large-v3-turbo`) и кэширует их в `provider_cache` под ключом `whisper_words_v3`.
3. `SanitizeWhisperTimeline` удаляет типовые галлюцинации тишины и применяет **Word Duration Clamping** (исправляет слова, растянутые на инструментальный проигрыш).
4. `needleman_aligner.go` выполняет глобальное DP-выравнивание Нидлмана–Вунша между словами эталонного текста и словами Whisper, интерполирует пропуски и привязывает строки к физическим стартам слов (`SnapLRCToAcousticWordsStats`). По умолчанию LLM-проход на этом этапе отключён; его можно включить флагом `KARAOKE_USE_GEMINI=true`.

## Атомарная запись `.lrc`

`AtomicLRCWriter` (`internal/lyrics/atomic_writer.go`) проверяет целевой путь через `PathGuard`, пишет файл во временный `.poisq_tmp_*.lrc` с правами `0644` и заменяет `<track>.lrc` через `os.Rename`.
