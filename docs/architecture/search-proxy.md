# Умный поиск и Subsonic-прокси (:4534)

Публичный сервер (`internal/proxy`, `internal/search`) работает прозрачным reverse proxy перед Navidrome. Все обычные запросы проходят без изменений, а поиск, биографии артистов, объявление OpenSubsonic-расширений и эндпоинты Cast обрабатываются перехватчиками.

## Какие маршруты перехватываются

| Маршрут | Обработка |
|---|---|
| `/rest/search`, `/rest/search2`, `/rest/search3` *(включая `.view` и префиксы `ND_BASEURL`)* | Извлечение запроса из `query`/`q`/`any` (GET или `application/x-www-form-urlencoded` POST до 1 МиБ), умный поиск и fan-out до 4 запросов к Navidrome с объединением JSON/XML. |
| `/api/search`, `/api/song*`, `/api/album*`, `/api/artist*` | Поддержка веб-интерфейса Navidrome и Feishin: рерайт параметров `title`/`name`/`_search`/`query`/`q` или JSON-параметра `filter` без fan-out (понижается регистр только не-ASCII символов). |
| `/rest/getArtistInfo2` *(включая `.view`)* | Подстановка проверенной русской биографии из `artistbio` и on-demand запуск генерации при её отсутствии. |
| `/rest/getOpenSubsonicExtensions` | Инъекция расширения `{"name":"poisq","versions":[1]}` в JSON и XML ответы Navidrome (`200 OK`, до 2 МиБ). |
| `/rest/poisqCast*` | Проверка Subsonic-авторизации через `/rest/ping` (кэш 5 минут) и передача в `internal/cast`. |
| `/_smart/test`, `/_smart/aliases` | Диагностика поиска и read-only просмотр алиасов (активны только при `ENABLE_DEBUG_API=true`, иначе `404`). |

## Поисковый словарь и алиасы

Словарь (`internal/search/dictionary.go`) строится из таблиц `artist`, `album` и `media_file` базы `navidrome.db` каждые `SYNC_INTERVAL` (`2m`) и индексируется одновременно в четырёх структурах в памяти:

- **Префиксное дерево (`Trie`)** — каждый узел кэширует до 20 лучших совпадений по убыванию веса, поэтому префиксный поиск работает за `O(L)`.
- **Точный индекс (`exactMap`)** — мгновенный lookup по строке.
- **Корзины по длине (`tokensByLen`)** — для нечёткого поиска в окне `[len - maxDist, len + maxDist]`.
- **Корзины по первой руне (`tokensByRune`)** — ускоряют нечёткий префиксный поиск.

Веса сущностей: исполнитель `1000`, альбом `500`, трек `100`, плюс `playCount × 5`. Для многословных названий дополнительно индексируются отдельные слова (от 2 символов, без 29 стоп-слов вроде `the`, `of`, `and`, `или`), привязанные к родительской сущности (`ParentEntity`).

Алиасы (`internal/search/alias_manager.go`, вес `800`) собираются по приоритету:
1. Встроенный `embedded_aliases.json` (**439** разговорных и транслит-алиасов, например `киш → Король и Шут`, `перцы → Red Hot Chili Peppers`, `метла → Metallica`).
2. Удалённый файл из `ALIASES_SYNC_URL` (обновляется через `5s` после старта и далее каждые `24h`, лимит `1 МиБ`).
3. Локальный `ALIASES_FILE` — наивысший приоритет, перезаписывает совпадения.

## Многоуровневый пайплайн обработки запроса

Для каждого входящего запроса (`internal/search/engine.go`) сначала генерируется набор вариантов (`GenerateVariants`): исходный текст, перевёрнутая раскладка QWERTY ↔ ЙЦУКЕН (`SwapLayout`), двусторонняя фонетическая транслитерация (`enMultiCharPatterns` — 66 правил, `ruMultiCharPatterns` — 39 правил), схлопывание и удвоение согласных (`of → off`, `offspring → ofspring`), замены `u↔oo`, `k↔c` и удаление артиклей `the`/`зе`/`де`.

Далее работают два режима (результаты кэшируются в `queryCache` до 4096 записей и сбрасываются при смене версии словаря):

1. **Короткие запросы (`≤ 3` рун)**:
   - префиксный поиск в `Trie` по вариантам (бонус `+1000` при совпадении алфавита с вводом);
   - нечёткий префиксный поиск (`dist ≤ 1`);
   - fallback на перевёрнутую раскладку.
2. **Длинные запросы (`≥ 4` рун)**:
   - быстрый проход: точное совпадение (`+2000`) и префиксный поиск по `Trie`, сбор до 4 уникальных кандидатов;
   - нечёткий поиск по фразе и префиксу на основе расстояния Дамерау–Левенштейна (`AllowedMaxDistance`: `0` для `≤2`, `1` для `3..4`, `2` для `5+` рун);
   - для многословных запросов — фразовое голосование (`MatchPhraseTokens`: каждое значимое слово голосует за родительскую сущность, побеждает сущность с `≥ 2` голосами) либо пословная нечёткая коррекция;
   - fallback на перевёрнутую раскладку.

## Fan-out, слияние и адаптация клиентов

`search.ExpandQuery` формирует до **4 уникальных запросов** в порядке приоритета: переписанный запрос (`RewrittenQuery`), исходный запрос, запрос без стоп-слов, альтернативная транслитерация/раскладка (`AlternateQuery`) и дополнительные кандидаты.

Если запросов больше одного или текст изменился, `FanoutManager` (`internal/proxy/fanout.go`):
1. Проверяет кэш ответов в памяти (`MemoryCache`: `2048` записей, TTL `45s` на сервере / `30s` для merged-ответов) с учётом `authKey` (SHA-256 от Subsonic-кредов и заголовков авторизации).
2. Коалесит идентичные параллельные запросы через `SingleFlight`.
3. Выполняет параллельные `GET`-запросы к Navidrome с общим таймаутом `5s` и лимитом ответа `10 МиБ` (потолок пагинации `artistCount`/`albumCount`/`songCount` — `500`, по умолчанию `20`).
4. Объединяет результаты (`merge_json.go` / `merge_xml.go`): дедуплицирует `artist`, `album` и `song` по полю `id` и обрезает до запрошенного лимита.

### Декорирование названий для сторонних клиентов

Многие сторонние Subsonic-клиенты (Arpeggi, Amperfy, play:Sub, iSub) повторно фильтруют выдачу сервера на устройстве по строке поиска пользователя и скрывают найденного `The Offspring`, если пользователь ввёл `офспринг`.

Для всех клиентов, кроме нативного `c=poisq`, прокси (`internal/proxy/client_adapter.go`) автоматически дописывает исходный запрос в скобках к `name`/`title`, если его там ещё нет:

```text
The Offspring → The Offspring (офспринг)
```

Клиент `c=poisq` получает чистые названия без скобок.

## Прокси-заголовки и CORS

- Если IP отправителя не входит в `TRUSTED_PROXIES`, сервер принудительно очищает входящие заголовки `Forwarded`, `X-Forwarded-*`, `X-Real-IP`, `True-Client-IP`, `CF-Connecting-IP`, `CF-Visitor` и `Remote-User`, предотвращая их подмену.
- Для запросов с заголовком `Origin` выставляется CORS (`Access-Control-Allow-Origin: <origin>`, без `Access-Control-Allow-Credentials`, `Vary: Origin`), а `OPTIONS`-запросы получают `204 No Content`.
